# SafePLC-Assist Box 产品测试报告

本文档说明 SafePLC-Assist Box 原型的产品级测试重点。测试目标是证明项目不仅是代码演示，而是具备安全边界、证据检查、本地图文证据显示和竞赛展示逻辑的可评审产品原型。

---

## 1. 测试范围

| 测试项 | 说明 |
|---|---|
| 产品界面 | Streamlit 界面是否能呈现工业知识问答终端 |
| 安全边界 | 是否清晰声明离线、只读和不控制 PLC 的边界 |
| 问题分类 | 是否能将用户问题分到合适处理类型 |
| 安全风险判断 | 是否能识别高风险 PLC 相关请求 |
| Evidence Confidence | 是否能判断证据支持程度 |
| Answer-Evidence Check | 是否能检查回答与证据一致性 |
| 结构化证据卡片 | 是否能以可复核方式展示证据 |
| 本地图文证据显示 | 本地环境中是否能显示对应图文证据 |
| 仓库边界 | 是否避免公开大型或版权敏感资产 |
| 硬件原型设计 | 软件状态是否能映射到实体终端指示 |

---

## 2. 测试目标

产品测试用于验证 SafePLC-Assist Box 是否具备：

1. 清晰的产品界面，而不是原始命令行演示。
2. 可见的工业安全边界。
3. 结构化证据复核流程。
4. 安全知识辅助与危险控制指令之间的明确区分。
5. 支撑后续实体原型展示的基础。

---

## 3. 安全边界测试

系统应明确说明：

- 不连接真实 PLC。
- 不接入 TIA Portal。
- 不执行 PLC 通信。
- 不执行 PLC 写入、下载、启停或控制动作。
- 不采集真实 IT / OT 网络数据。
- 不替代西门子官方手册或具备资质的工程师。

对于高风险 PLC 控制请求，系统应避免提供可执行控制步骤，并引导用户参考官方资料、现场安全规程和专业工程复核。

---

## 4. 证据能力测试

### 4.1 Evidence Confidence

系统应判断当前回答是否有足够证据支持。证据不足、缺失或冲突时，应提示需要复核。

### 4.2 Answer-Evidence Check

系统应检查回答关键声明是否被证据支持，并给出 PASS、REVIEW 或 FAIL 等结果。

### 4.3 结构化证据卡片

证据卡片应展示 card_id、evidence_type、confidence、page、figure_id、source、title、module、parameter 和 snippet 等信息，便于评审者追溯。

### 4.4 本地图文证据显示

当证据卡片包含页码或 `figure_id` 时，前端会尝试在本地演示环境中显示对应图文证据。

示例：

```text
page: 641
figure_id: page_0641_visual
```

对应文件示例：

```text
page_0641.jpg
```

完整图文证据资产不包含在公开仓库中。

---

## 5. 硬件原型测试

软件状态应能映射到计划中的硬件指示：

| 软件状态 | 硬件指示 |
|---|---|
| 低风险知识查询 | SAFE |
| 缺少上下文或中风险问题 | CAUTION |
| 高风险 PLC 操作请求 | HIGH_RISK |
| Evidence Confidence 完成 | CHECK |
| Answer-Evidence Check 完成 | CHECK |

硬件设计应清楚表达系统是知识辅助终端，而不是 PLC 控制器。

## 7. 限制说明

当前测试基于原型环境。公开仓库不包含完整西门子手册、完整 OCR 输出、向量库、模型权重、完整图文证据资产、token、环境文件或压缩交付包。

实体终端外壳仍在进行中，最终照片和演示视频将在后续完善阶段补充。

## 8. 总结

当前产品测试表明 SafePLC-Assist Box 已具备产品化界面、安全边界、安全风险判断、Evidence Confidence、Answer-Evidence Check、结构化证据卡片、本地图文证据显示逻辑和硬件终端设计映射。
